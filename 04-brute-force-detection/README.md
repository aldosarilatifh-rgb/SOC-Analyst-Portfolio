# محاكاة واكتشاف هجوم SSH Brute-force

## نظرة عامة

محاكاة هجوم Brute-force حقيقي (بأداة اختبار اختراق معروفة) ضد بيئة محلية آمنة، وقياس فعالية قواعد الكشف الافتراضية والمخصصة في التقاطه.

**الأدوات المستخدمة:** Hydra، SSH، Wazuh

## منهجية آمنة

- الهجوم استهدف الجهاز نفسه فقط (`127.0.0.1`) — لا اتصال بأي شبكة خارجية
- استُخدمت قائمة كلمات مرور خاطئة عمداً — لا احتمال لنجاح الدخول الفعلي
- لم يُفعَّل أي Active Response يحظر تلقائياً، لتجنب قفل الوصول للجهاز عن طريق الخطأ

## تنفيذ الهجوم

```bash
hydra -l kali -P /tmp/test_passwords.txt ssh://127.0.0.1
```

النتيجة: 5 محاولات دخول فاشلة متتالية بسرعة — نمط يحاكي بنية هجوم Brute-force حقيقي بحجم مصغّر وآمن.

## النتائج

**بالقواعد الافتراضية:** كل محاولة سجّلت كحدث منفصل بمستوى خطورة 5 (`sshd: authentication failed`)، دون أي ربط تلقائي بين الأحداث الخمسة.

**بعد إضافة قاعدة ارتباط مخصصة** (`frequency=5`, `timeframe=60`):
rule.id: 100003 | rule.level: 10
"تحذير: 5 محاولات SSH فاشلة خلال دقيقة - احتمال Brute-force!"


ظهر تنبيه إضافي واحد يلخّص النمط الكامل بمستوى خطورة أعلى وأوضح.

## الدرس المنهجي

هذا التمرين يوضح فجوة حقيقية شائعة في أنظمة SIEM الجاهزة: التغطية الافتراضية قد تكون قوية لبعض أنواع الأحداث (مثل sudo) وضعيفة لأخرى (مثل SSH) رغم تشابه طبيعة الهجوم. دور محلل SOC الجيد يتضمن ملاحظة هذه الفجوات وسدّها بقواعد مصممة بدقة، لا الاكتفاء بالإعدادات الافتراضية.
