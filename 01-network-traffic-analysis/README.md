# تحليل حادثة Exploit Kit — Drive-by Download

## نظرة عامة

تحليل ملف pcap حقيقي من موقع [malware-traffic-analysis.net](https://www.malware-traffic-analysis.net/) لحادثة أمنية شملت 3 أجهزة Windows، بهدف تحديد الجهاز المصاب ونقطة الدخول وسيرفر الهجوم.

**الأدوات المستخدمة:** Wireshark

## السيناريو

3 أجهزة Windows نشطة على نفس الشبكة. على الأقل جهاز واحد زار موقعاً يحتوي Exploit Kit. المطلوب تحديد أي الأجهزة أصيب فعلياً.

## منهجية التحقيق

1. **تحديد الأجهزة الثلاثة** عبر فلتر `nbns` (بروتوكول NetBIOS لكشف أسماء أجهزة Windows)
2. **رصد نشاط غير طبيعي** عبر `Statistics → HTTP → Requests` — لاحظت نطاقاً بأسماء مسارات عشوائية (كلمات قاموس بلا معنى) وبورت غير قياسي
3. **تحديد الجهاز المتأثر** عبر `tcp.port == [البورت المشبوه]`
4. **تتبع التسلسل الزمني** لآخر نشاط طبيعي قبل الإصابة مباشرة عبر `frame.time_relative`
5. **التحقق الرسمي** من هوية IP المشبوه عبر أمر `whois` (بدل الاعتماد على التخمين من أسماء الملفات)

## النتائج

| العنصر | القيمة |
|---|---|
| **الجهاز المصاب** | MYHUMPS-PC (`192.168.204.137`) |
| **نقطة الدخول** | موقع فرنسي مخترق — `www.theopen.be` (`213.186.33.19`) |
| **سيرفر Exploit Kit** | `epzqy.iphaeba.eu` (`168.235.69.248:22780`) |
| **الأجهزة السليمة** | ROCKETMAN-PC، WORKSTATION6 |

النتائج طابقت 100% الإجابات الرسمية المنشورة على الموقع المصدر للتمرين.

## الاستنتاج الفني

نمط **Drive-by Download** كلاسيكي: الضحية زارت موقعاً شرعياً مخترقاً (compromised website)، وتم تحويلها تلقائياً وبصمت (hidden redirect) لسيرفر استغلال ثغرات (Exploit Kit) بدون أي تفاعل من المستخدم (لا نقر ولا تحميل).

**مؤشرات كشف الـ Exploit Kit:**
- مسارات URL بأسماء كلمات إنجليزية عشوائية بلا معنى منطقي (تقنية تهرب من أنظمة الكشف التقليدية)
- بورت شبكة غير قياسي (22780 بدل 80/443)
- معرّفات جلسة رقمية طويلة في كل طلب (فريدة لكل ضحية)

## الدرس المنهجي

لا يجب الاعتماد على استنتاج بصري (مثل تخمين جنسية موقع من أسماء ملفاته) دون تحقق رسمي بأداة مخصصة (`whois`, GeoIP) — قاعدة أساسية لضمان دقة أي تقرير أمني.
