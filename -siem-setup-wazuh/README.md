# إعداد SIEM من الصفر — Wazuh

## نظرة عامة

تنصيب وإعداد نظام Wazuh SIEM كاملاً على بيئة Kali Linux، شاملاً Manager وDashboard، وربطه بمراقبة فعلية للنظام.

**الأدوات المستخدمة:** Wazuh 4.9، Kali Linux (VMware)

## الإعداد التقني

- تثبيت Wazuh Manager + Dashboard (تنصيب موحّد `-a`)
- ضبط موارد الجهاز الافتراضي (رام 4GB كحد أدنى) لتشغيل الخدمة بثبات
- تفعيل **File Integrity Monitoring (FIM)** لمراقبة مجلدات وملفات محددة في الوقت الفعلي (`realtime="yes"`)
- قراءة وتحليل Dashboard: توزيع التنبيهات حسب مستوى الخطورة (Critical/High/Medium/Low)، وربطها بإطار **MITRE ATT&CK**

## اكتشاف تقني مهم

قواعد Wazuh الافتراضية تفرّق بين أنواع أحداث الملف:
- **إضافة ملف جديد** → مستوى خطورة أقل (نشاط طبيعي متكرر)
- **تعديل أو حذف ملف موجود** → مستوى خطورة أعلى (أكثر دلالة على تلاعب متعمد)

كل تغيير يُتحقق منه عبر **checksum** (بصمة رقمية لمحتوى الملف)، وليس فقط التاريخ أو الحجم — هذا يكشف محاولات التهرب التي تعتمد على تزوير طابع زمني قديم.

## مهارة Alert Triage

عند مواجهة تنبيه، اتباع تسلسل ثلاثي:
1. **من؟** مصدر الحدث (مستخدم/جهاز متوقع أم لا)
2. **ماذا بالضبط؟** نوع الحدث ومساره
3. **هل يوجد سياق يفسره؟** (حدث لاحق يغلق القصة منطقياً، أم تبقى مفتوحة)

القاعدة الذهبية: **لا يُقفل أي تنبيه بدون دليل يفسره.**

## الدرس المنهجي

أول تشغيل لأي SIEM جديد ينتج "ضجيج" كبير من تنبيهات روتينية (بدء الخدمة، فحوصات تلقائية أولية). التمييز بين هذا الضجيج والتهديد الحقيقي هو جوهر مهارة محلل SOC L1.
